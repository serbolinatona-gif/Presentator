# Presentator — бесплатный AI-генератор презентаций

Введи тему → AI сгенерирует структуру, текст и подберёт изображения для каждого слайда →
получи готовую презентацию: превью в браузере + файл `.pptx`. Без регистрации, без платных подписок.

## Как это работает

1. **Структура** — GigaChat API строит план из N слайдов (заголовки + тезисы).
2. **Наполнение** — для каждого слайда GigaChat генерирует заголовок, 3–5 буллетов и ключевые слова для картинки.
3. **Изображения** — по ключевым словам подбирается фото через Picsum Photos (1920×1080, без ключа и регистрации). Если ключевых слов нет — используется градиентная заглушка.
4. **Сборка** — собирается лёгкий самодостаточный HTML-превью (для показа во встроенном iframe) и файл `.pptx` через `python-pptx`.

Прогресс каждого этапа стримится на фронтенд через Server-Sent Events — как печатающий ответ в ChatGPT.

> **Важно про архитектуру:** в ТЗ упоминался Slidev. Полноценный Slidev — это отдельный
> Node/Vue build-пайплайн, который плохо уживается с бесплатным Python-хостингом в одном сервисе.
> Поэтому вместо него бэкенд сам генерирует HTML со слайдами, анимациями и навигацией
> (`backend/slidev_builder.py`) — визуально то же самое, но без лишней инфраструктуры.

> **Почему GigaChat, а не Gemini/OpenAI:** сервисы Google/OpenAI/Pexels требуют регистрацию
> и привязку аккаунта, недоступные из России даже через VPN (блокировка на уровне
> верификации, а не только по IP). GigaChat — российский сервис (Сбер), регистрация через
> обычный аккаунт на developers.sber.ru/studio, без VPN. Picsum — вообще без ключа и
> регистрации, работает из любой страны.

## Стек

- **Frontend:** React 18 + Vite + Tailwind CSS + Framer Motion + lucide-react
- **Backend:** FastAPI + httpx + python-pptx + Pydantic
- **AI:** GigaChat API (Сбер, бесплатный персональный тариф)
- **Изображения:** Picsum Photos (бесплатно, без ключа и регистрации)
- **Хостинг:** Render (бесплатный план)

## Получение бесплатного ключа GigaChat

1. Зайди на https://developers.sber.ru/studio (обычный российский Sber ID / телефон, VPN не нужен).
2. Создай проект → выбери **GigaChat API** → тариф **"Бесплатный"** (лимит токенов в месяц, этого достаточно для тестов и небольшого продакшна).
3. В настройках проекта найди **"Authorization key"** (это готовый Base64-ключ client_id:client_secret) — скопируй его целиком.
4. Это и есть значение `GIGACHAT_AUTH_KEY` в `.env`.

Изображения через Picsum ключа не требуют — работает сразу из коробки.

> Если в будущем понадобится честная TLS-проверка сертификата GigaChat (по умолчанию она
> отключена, `GIGACHAT_VERIFY_SSL=false`), скачай "Минцифры Root CA" с госуслуг/сайта Минцифры
> и подключи путь к нему в `httpx.AsyncClient(verify=...)` в `generators.py`.

## Запуск локально

### 1. Бэкенд

```bash
cd backend
python -m venv venv
source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements.txt

cp ../.env.example .env
# впиши свой GIGACHAT_AUTH_KEY в backend/.env

uvicorn app:app --reload --port 8000
```

Бэкенд поднимется на `http://localhost:8000`, health-check: `http://localhost:8000/api/health`.

### 2. Фронтенд

```bash
cd frontend
npm install
npm run dev
```

Открой `http://localhost:3000` — Vite проксирует запросы `/api/*` на бэкенд (см. `vite.config.js`).

## Деплой на Render

1. Запушь проект в свой GitHub-репозиторий.
2. На https://dashboard.render.com нажми **New → Blueprint**, укажи репозиторий — Render найдёт `render.yaml` и сам создаст два сервиса (backend + frontend).
3. В настройках сервиса `slideforge-backend` добавь переменную окружения:
   - `GIGACHAT_AUTH_KEY`
4. Нажми **Deploy**. Через пару минут оба сервиса будут доступны по адресам вида
   `https://slideforge-backend.onrender.com` и `https://slideforge-frontend.onrender.com`.

> На бесплатном плане Render сервис "засыпает" после 15 минут бездействия — первый запрос после паузы
> может занять 30–60 секунд на "пробуждение". Это ограничение бесплатного тарифа, не проекта.

## Обработка ошибок

- Если `GIGACHAT_AUTH_KEY` не задан, токен истёк или GigaChat не отвечает — пользователь увидит
  понятное сообщение ("AI не ответил, попробуй ещё раз") вместо падения интерфейса.
- Если по слайду не набралось ключевых слов для картинки — слайд получает градиентную заливку вместо фото.
- Все ошибки бэкенда логируются в консоль (`logging`), удобно для отладки на Render (вкладка Logs).

## Известные ограничения / что можно улучшить дальше

- Презентации хранятся в памяти процесса (`PRESENTATIONS` dict) и очищаются через 6 часов.
  Для продакшна с несколькими воркерами это стоит заменить на Redis или БД (SQLite/Postgres).
- Фронтенд написан на JSX, а не TypeScript — если нужна строгая типизация, компоненты
  несложно перевести в `.tsx` с типами пропсов.
- Реферальная программа и галерея "лучших презентаций" из ТЗ — в этой версии не реализованы,
  оставлены как идея для следующей итерации.
